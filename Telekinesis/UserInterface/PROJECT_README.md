# Telekinesis — frontend

Vue 3 + TypeScript + Vite + Pinia + vue-router (hash history) + Tailwind v4. UI template: `UI templates/minimal-ui-components.html` (light tokens in `src/assets/main.css`). **Deliberate deviation for the game stage:** pure white background, black outlines, no fills.

## Structure
`src/views` · `src/components` (`icons/` = shared `AppIcon`, mandatory) · `src/stores` · `src/services` (`httpClient.ts` is the only `fetch`; `appApi.ts` mirrors `Api/AppEndpoints.cs`) · `src/router` · `e2e/` Playwright (icon audit).

## Conventions
- Every clickable has an icon (icon audit in `e2e/icons.spec.ts`).
- `data-testid` on interactive elements. No `fetch` outside `httpClient.ts`.
- Build output goes to `../wwwroot` (served by the desktop host).

## Game structure
`src/game/` is plain TypeScript with no Vue/DOM (unit-tested in `__tests__`); `views/GameView.vue` owns the canvas, the rAF loop and the HUD. New movement features (circling, free movement, speed, shooting) = new behaviours in `Swarm.step` keyed off a pose/mode, each with a physics test.
- 0.3.0 — **Circling + hand no longer steers**: the hand chooses the behaviour only (`SwarmInput` has no position). Balls gather at a fixed hover point (upper-middle of the window). Two fingers (index + middle out, ring + pinky curled → new `two` pose) = circle: the cloud orbits the hover point (inner balls swirl faster, spin eases in/out). Pinch (continuous `pinchAmount`) tightens the cloud in any floating mode. Single index finger = `point` pose, recognised but unused (reserved for free movement / shooting). Mouse fallback: hold = levitate, + Shift = circle, + Alt = tighten, release = drop.
- 0.4.0 — **Free movement**: single index finger (`point` pose) = move. The finger's direction (knuckle → tip, mirrored to screen space, smoothed, unit length: `HandSignals.pointDir`) moves the hover point at a fixed speed (`TUNING.moveSpeed`, scales with the window); the swarm follows through the spring, so it stretches in the direction of travel. The hover point is clamped inside the window; it stays where it ends (open palm = hover there, fist = drop there, pinch/none = hold). Speed control is the next step. Mouse fallback: hold + arrow keys / WASD.
- 0.5.0 — **Force-based physics (no more target chasing)**: the swarm no longer springs to fixed target points. Gestures apply forces to velocities and momentum does the rest: gravity fades out per ball as it levitates, air drag fades in; a soft cohesion pulls stragglers toward the swarm's own average point; move = a push along the finger (terminal speed = push / drag, so speed ramps up and coasts down); circle = sideways push + inward binding around the average point (spin builds gradually); pinch tightens the cohesion radius; a collective, damped hover thrust (the same acceleration for every ball) holds the swarm's average point in the air. Pickup from the floor gathers at the swarm's current average point and rises to `hoverHeight` (~28% of the window height) above the floor — not to the last hover spot. Stopping a move with open palm / two fingers brakes where the swarm is. Walls and floor just bounce balls (restitution 0.45).
- 0.6.0 — **Gradual hand-overs + pointing as a stream**: (1) move → circle/levitate no longer grabs the centre: the collective hover thrust fades in slowly (`holdRampUp`) while its hold point follows the swarm, so the centre keeps coasting and slows by drag; the circle's spin also ramps in/out (`spinRamp`). (2) Pointing draws an invisible line from the swarm's average point along the finger. Each ball gets an engagement `e` (0..1) that switches on when the stream reaches it — nearest to the line first (`streamSpread`), balls ahead of the swarm before those behind (`streamFront`) — and rises/falls smoothly. Engaged balls feel a push along the line, sideways-velocity damping (velocity turns to the line) and a pull toward the line (`streamAlign`, `streamPull`). A sharp finger turn (> 50°) restarts the spreading so the stream sweeps round. Leaving `point` fades `e` instead of cutting the push.
- 0.7.0 — **Bigger scene + slower stream**: the simulation now has its own units, independent of the window (`TUNING`: ball radius 10, cloud 175, hover height 360, gravity 4500, move speed 900, floor margin 110). The view draws the world scaled by `VIEW_ZOOM` (`game/config.ts`, 0.32): balls are ~3 px and the window shows ≈3.1× more world per direction (≈10× the area); the balls start as a heap in the middle of the floor. Change `VIEW_ZOOM` for a different scale (smaller = tinier balls, more room). A soft ball-to-ball repulsion (`repelRange/Strength`) lets a squeezed swarm re-inflate instead of staying a dense strip. The pointing stream now spreads over ~1 s (`streamSpread` 1.5, `streamFront` 3.2, `streamRise` 5): near-line balls first (44 % caught at 0.4 s vs 1 % for the farthest), all caught by ~1 s.
- 0.8.0 — **Comet movement** (from the user's sketch: round → teardrop with a pointed head → long thin streak, head leading): the stream now catches the *head* first (per-ball `tau`, fixed when pointing starts or turns sharply: furthest ahead along the finger first, then back along the swarm, `streamFront`), the head gets a stronger push (`streamHeadBias`) and a tighter pull onto the line (narrow tip, looser tail), and cohesion is measured so the swarm may elongate along the line up to (1 + `streamStretch`)× the cloud radius but not sideways; when pointing stops it eases back into a cloud. **Faster and faster:** while you keep pointing, a `charge` grows (decays at 1.5/s when you stop) that scales the push (`boostBase` → `boostMax`, convex over `boostTime`) and eases the air drag off on caught balls (`streamDragCut`), so the speed gain keeps rising (≈230 → 760 → 1450 → 2900 world units/s at 0.8/1.6/2.4/3.2 s). Ball-to-ball repulsion keeps the swarm from collapsing into a line.
- 0.9.0 — **Open palm = gravity off; pinch gathers; centre = front ball while moving**: the hover hold / collective thrust / automatic gathering are gone. Open palm only switches gravity off (fast `liftRate`): balls keep their velocity and only the air drag slows them (plus a tiny `wanderAccel` drift). From the floor each ball gets a small random upward kick (`kickUp`, `kickSide`) so you can see it "woke up". Pinch pulls balls toward a centre (`pinchPull`, `pinchDamp`, scaled by the eased pinch amount); circle swirls around the same centre. The centre (`Swarm.anchor`) is the swarm's middle when it is (nearly) still, and **the front ball when the swarm is moving** (centroid speed > `movingSpeed`): it keeps the head's velocity and coasts/slows with the air drag like a ball, so the tail curls in around the head. It is created when a pinch (> 0.15) or circle starts and cleared when neither is happening. Cohesion toward the middle now only applies in `move`. The stream timing no longer depends on swarm size: it reaches head-to-tail in `streamReachTime` (0.55 s) + `streamSideTime` for off-line balls.
- 0.10.0 — **No hidden spreading/clumping**: the soft ball-to-ball repulsion is gone — balls may touch freely (only a position correction stops them interpenetrating; no force), a clump stays where it is after the pinch is released, and a floating swarm neither spreads nor clumps by itself. **Starting to point no longer clumps first:** the cohesion that used to run from the first frame of `move` (and fought the head's push) is now applied only to balls the stream has already reached (scaled by their engagement `e`) with a generous fixed elongation limit; balls it hasn't reached yet feel nothing and simply keep their own velocity (air drag only). The stream still catches the head first and works back (`streamReachTime`), each ball joining as it is reached.
- 0.11.0 — **Facing: a fist only counts as a fist with the palm toward the camera.** `HandSignals.facing` (`palm` | `back`, smoothed score + the two cues) from `facingCues`: (1) *winding* — signed area of wrist / index knuckle / pinky knuckle in the raw image, whose sign flips when the hand is turned over and depends on the hand label (derived: right hand, palm to camera ⇒ cross < 0), fades to 0 edge-on, works for fists because the knuckles don't move; (2) *depth* — curled fingertips in front of the knuckles ⇒ palm to the camera, behind ⇒ back; weighted by (1 − openness). Smoothed (`facingSmoothing`), dead zone (`facingDeadZone`) keeps the previous answer when edge-on; the first frame of a hand is taken as read. `classify(extended, pinching, facing)`: a back-facing fist is reported as `open` (so the game logic is unchanged: fist toward the camera = drop, fist turned away = floats like open palm). Pinch / point / two ignore facing. The spike page shows the facing + the two cues per hand and logs facing changes. Verified on a real webcam (macOS window): the user confirmed the readout matches.
- 0.12.0 — **Open palm + a moving hand = a slow drift of random balls the way the hand moves.** `SwarmInput.drift` = the hand's velocity (frame-heights/s, mirrored screen space; `HandSignals.velocity`), only used with `open` while floating. Strength comes from the hand speed (`driftDeadZone` 0.25 ignores jitter → `driftFull` 1.0 = full), direction from its motion. Each ball has its own slow random "gust" (a sine of its private phase/frequency) and is only picked while the gust is above `driftPickFrom` (smoothstep over `driftSoft`), so a changing random subset follows; picked balls are pushed with a terminal speed of `driftSpeed` (300 units/s ≈ 95 px/s on screen), the rest just coast. When the hand stops the balls keep their velocity and only the air drag slows them (no hold). Position of the hand still never steers anything. Mouse fallback: hold + move the mouse (its velocity stands in for the hand).
- 0.13.0 — **The closer the hand, the more the wave drifts the balls.** `SwarmInput.reach` (0..1) = `handReach(hand.size)` in `game/input.ts`: the hand's size on screen (wrist → middle knuckle / frame height; ≈0.10 at about a metre → 0, ≈0.20 at a laptop's arm's length → 0.5, ≈0.30 very close → 1; `REACH_FAR_SIZE` / `REACH_NEAR_SIZE`). It scales both *how many* balls are picked (`driftPickFar` 0.5 → `driftPickNear` −0.7: ~2/60 → all 60 moving) and *how fast* they drift (`driftGainFar` 0.3× → `driftGainNear` 1.7× the 300 units/s base). Same 3 s wave: far ≈ 12 px, middle ≈ 92 px, near ≈ 228 px on screen; the fastest ball tops out at ~500 units/s. The spike page shows the hand size next to the speed (target icon). Mouse fallback: the wheel is the hand distance (wheel up = closer).
- 0.14.0 — **Air drag halved** (`TUNING.airDrag` 1.2 → 0.6): floating balls (and the pinch/circle centre, which coasts like a ball) keep their velocity twice as long. The pointing push and the hand drift are now tied to a fixed `pushRefDrag` (1.2) instead of `airDrag`, so the gestures push exactly as hard as before — only the decay changed (top speeds are therefore higher: ~2140 vs 1640 units/s after 2.5 s of pointing, the drift's fastest ball up to ~1000 vs ~500 units/s at full reach). After releasing a 2.5 s point: half speed after 1.9 s (was 1.1 s), <5 % after 5.7 s (was 3.1 s), coasting a further ~4950 units (was ~2160) — more than the whole window is wide (3400 units at the default zoom), so a released comet now crosses the stage and bounces off the wall.
- 0.15.0 — **Zoomed out 2×** (`VIEW_ZOOM` 0.32 → 0.16 in `game/config.ts`): balls are ~1.6 px in radius on screen, the window shows ~6.3× more world per direction (≈ 6800 × 4400 world units at 1100 × 700 px). Nothing in the physics changed (it all runs in world units), so on-screen distances and speeds look half as large. The e2e ink helper now finds the floor line as "a pixel row that is mostly ink" instead of assuming a fixed band, so it works at any zoom.
- 0.16.0 — **Speed control + stop gesture.** (1) *Speed control:* while pointing, the hand distance (`SwarmInput.reach`, eased by `reachEase`) scales the push (`speedGainFar` 0.4× … `speedGainNear` 1.6×, middle = 1×) AND sets the top speed the pointing can build to (`speedCapFar` 1500 … `speedCapNear` 6000 units/s, middle ~3500) via an extra drag on stream-carried balls only (`overspeedDrag`), so open-palm coasting is never capped. This also fixed a runaway: with the halved air drag the "faster and faster" push had no ceiling (≈9400 units/s after 5 s). Mouse wheel = hand distance. (2) *Stop gesture:* **both hands open** (an open palm in each; back-facing fists count) held for 0.3 s (`STOP_HOLD`; released 0.15 s after either leaves, `STOP_GRACE`) — `StopDetector` in `game/input.ts`, `SwarmInput.stop`. It eases in a strong extra drag (`stopDrag` 6/s, `stopEase` 10/s ⇒ ≈ 0.5 s to a standstill: 2170 → 155 units/s in 0.5 s), lets go of the pointing stream at once, switches the wave-drift off, then the swarm just keeps floating where it stopped. HUD pill "stop"; mouse: hold + Space.

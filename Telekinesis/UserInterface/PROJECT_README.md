# Telekinesis — frontend

The whole game lives here: camera → hand tracking → gestures → swarm physics → canvas. The backend (`../`) only hosts the window and a tiny local API.

## Stack
Vue 3 (`<script setup lang="ts">`) · TypeScript · Vite · Pinia (setup stores) · vue-router (**hash history**, the desktop host serves a static `index.html`) · Tailwind CSS v4 (`@tailwindcss/vite`, tokens in `src/assets/main.css`) · MediaPipe Tasks Vision (`@mediapipe/tasks-vision`, Hand Landmarker) · planck.js (a Box2D port: the Arena's rigid bodies) · Vitest · Playwright. Node `^22.18` or `>=24.12`.

Build output goes to `../wwwroot` (served by the desktop host in Release).

## How it works
1. **`useHandInput`** reads frames from the webcam (unmirrored) and runs the Hand Landmarker (≤ 2 hands).
2. **`GestureTracker`** (`helpers/gestures.ts`) turns the 21 landmarks per hand into `HandSignals`. Everything is distance based, so it works with any hand or camera rotation. MediaPipe's `Left`/`Right` label is used as is (for unmirrored frames it is already the user's own hand).
3. **`game/input.ts`** maps the primary hand (right preferred) to a `SwarmInput` = `{ pose, dir, pinch, drift, reach, stop, follow? }`. The hand **chooses the behaviour; it never places the balls** (no position in `SwarmInput`) — the one exception is avatar mode's `follow` (below). `StopDetector` watches both hands.
4. **`Swarm.step(dt, input)`** advances the simulation. Every gesture is *one force on velocity*; momentum, air drag, walls and gravity do the rest.
5. **`GameView`** draws it: white stage, black outlines only, no fills.

**Avatar mode** (optional): `GestureCode` watches the primary hand's pose; performing the code toggles the mode (as does the toggle button). `AvatarSmoother` turns the primary hand's raw landmarks into a steady pose — palm position (One Euro + dead-band), each joint's palm-relative coordinates (One Euro), and a lightly smoothed hand size to normalise by — and `GameView` draws the spike's skeleton at `AVATAR.handPx` (a very small, **constant** size, however close the hand is) at the palm's screen position. `applyAvatar` then gives the back-facing fist (`HandSignals.fistBack`) a meaning: the swarm circles around the avatar, and `Swarm` takes that point (canvas px ÷ `VIEW_ZOOM`) as a kinematic centre, so the circle follows the hand.

**Arena** (optional, `/arena`): `GameView` creates an `Arena` for the world size. Each frame, after the swarm's own step, `Arena.update` applies the distractors to the floating balls, runs `couple` (ball ↔ prop contacts, with impulses on the props), steps the planck world in fixed 1/120 s sub-steps, then reads the solver's impacts and the balls' hits to apply the rules (pop, ring, crash, domino fallen), the goal, the score and the combo. The view draws the props and distractors under the balls, the effects over them, and plays the sounds for the drained events.

Without a camera the mouse stands in for the hand (see the table below).

## Gestures
| Hand | Effect |
|---|---|
| **Open palm** (a fist with the *back* toward the camera counts as open) | Gravity off. Balls keep their velocity; only the air drag slows them. From the floor each ball gets a small random upward kick. **Waving** the open hand drifts a random, changing subset of balls slowly the way the hand moves; the closer the hand, the more balls and the faster. |
| **Fist** (palm toward the camera) | Gravity back on — the swarm drops with the speed it had. |
| **Point** (index only) | Move: an invisible line grows from the swarm along the finger; the ball at the head is caught first, then it works back, so the swarm stretches into a comet. The push grows the longer you hold it. **Hand distance sets the speed** (a close hand pushes harder and reaches a higher top speed). |
| **Two fingers** (index + middle) | Circle around the centre point. |
| **Pinch** (thumb + index) | Pull the balls together toward the centre point (works in every floating mode; releasing leaves the clump where it is). |
| **Both hands open**, held ~0.3 s | Stop: brake to a standstill, then keep floating there. |

*Centre point* (circle / pinch) = the swarm's middle, or **the front ball if the swarm is moving**; it keeps coasting with that ball's own velocity.

**Avatar mode** — switch it on or off with the **gesture code** (hold each ~0.25 s, the whole thing within ~6 s: **fist → point → two fingers → open palm**) or the avatar button in the top bar. Then: your hand is drawn as a tiny constant-size character at its position (one hand at a time, strongly smoothed), and a **fist with the back toward the camera** (normally just an open palm) makes the balls circle **around the avatar, following it**. Everything else works as above.

**Mouse fallback** (the mouse button in the game's top bar): hold the button = open palm · move the mouse = wave · **Shift** = two fingers · **arrow keys / WASD** = point · **Alt** = pinch · **Space** = both hands open · **wheel** = hand distance · **B** = fist with the back toward the camera (avatar mode) · release = fist. The avatar button in the top bar switches avatar mode; in avatar mode the pointer is the avatar.

## Arena
The same swarm, stage and gestures as `/play`, plus things to hit, a goal, a score and sound. All outlines, no fills.

| Object | What it does |
|---|---|
| **Crate**, **domino**, **boulder** | Rigid bodies: knock, topple, roll. Crates 120 units, light and a little slippery (density 1.4, friction 0.35) so a comet can topple a stack. |
| **Wrecking ball** | A heavy ball on a rigid rod: swing it with the swarm. |
| **Balloon** | Floats up on a rope; **pops** when hit at ≥ 4 m/s (a drifting brush doesn't), by a ball or a falling prop. |
| **Gong** | **Rings** when hit at ≥ 1.5 m/s; the first ring counts for the goal, later ones are worth less; re-arms after 0.5 s. |
| **Lantern** | Lures floating balls within ~900 units (pull + swirl): moths to a flame. |
| **Fan** | A wind zone, 3 s on / 3 s off (starts off), pushes floating balls and balloons. |
| **Whirlpool** | Pulls and swirls floating balls; one that reaches the core is **recycled to the start heap** (the swarm stays at 60). Props are unaffected. |

Stages (`game/stages.ts`): **1 Pop Garden** (pop 8 balloons; two sit right above the heap) · **2 Pyramid & Gongs** (ring 3 gongs) · **3 Domino Rally** (topple 24 of 30) · **4 Wrecking Ball** (knock 12 crates of a 2×10 tower sideways) · **5 Moths & Whirlpool** (6 balloons + 2 gongs among lanterns, a fan and a whirlpool). Every stage starts perfectly calm (tested).

Score and combo: pop 100 · first gong ring 250 (later 25) · domino 20 · hard crash 10 · stage clear +1000. Every scoring event inside 2.5 s of the previous one raises the combo; points × min(8, combo). **Sound:** each scoring event plays the next step of a pentatonic ladder (so a chain reaction becomes a little tune); pops, thuds and gongs have their own voices; the sound button mutes.

**Tuned with probes** (the real swarm flying into real props): ball mass 0.2 kg (the swarm ≈ 12 kg). At 0.04 a comet hit a tower 200+ times and moved it 3 units; at 0.4 a lone crate rocketed away at 16 m/s. Now a low hit on the tower tumbles ~8 of 20 crates, a high one ~16; the pyramid shrugs off a low hit. Whirlpool pull 4800 / swirl 550 (at swirl 1600 the balls just orbit it).


## Conventions
- **Hand never steers** — except avatar mode's circle, whose centre follows the avatar on purpose (`SwarmInput.follow`). `SwarmInput` otherwise has no position; a new gesture = a new pose or value in `SwarmInput` + one force in `Swarm.step`, with a physics test.
- **Anything drawn from the hand must be smoothed** (`AvatarSmoother`): tracking jitter is fine for gestures but not for a character. Normalise by size so it never scales with the hand's distance.
- **No hidden "comfort" forces** (no spacing / gathering unless a gesture asks for it). A gesture's forces act on a ball only once that gesture has reached it (its engagement `e`); everything else just coasts.
- **The simulation has its own units** (ball radius 10, cloud 175, gravity 4500, … in `TUNING`), independent of the window. `VIEW_ZOOM` only decides how much of the world is visible (0.16 → balls ≈ 1.6 px radius, window ≈ 6800 × 4400 world units). Pushes are tied to a fixed `pushRefDrag`, so changing `airDrag` only changes how long things coast.
- **Two physics worlds, one coupling.** The swarm keeps its own force model (world units, `TUNING`); the Arena's props are planck bodies (metres: 100 units = 1 m, gravity +y). Only `game/coupling.ts` makes them touch; every ball collides with every prop, and the contact impulse goes to the prop AT the contact point. A body that cannot rotate (a balloon) has **zero inertia** — never divide by it (that once made balloons unpushable, and NaN poisoned planck).
- **Arena stages are data**: a builder per stage in `game/stages.ts`, positions as offsets from the centre in a 6875-unit design space (squeezed in x on a narrow window), fixed physical sizes. A new object = a prop kind in `physics.ts` + a drawing in `arenaDraw.ts` + a rule in `arena.ts`, with a test; a new stage must pass the "builds inside the world / no overlaps / starts calm" tests.
- **All tuning numbers live in `TUNING`** (`game/swarm.ts`) and `THRESHOLDS` (`helpers/gestures.ts`), each with a comment. Change a number there, not in the logic.
- API calls only through `services/*Api.ts` → `httpClient.requestJson`. `diagnosticsApi.reportDiagnostic` prints UI status lines to the host console (the WebView console isn't readable from a terminal).
- **Every clickable has an icon** (`AppIcon`); icon-only controls carry `title` + `aria-label`; interactive elements have a `data-testid`. Enforced by `e2e/icons.spec.ts`.
- UI template: `UI templates/minimal-ui-components.html` (light tokens in `src/assets/main.css`). **Deliberate deviation for the stage:** pure white background, black outlines.

## Testing
- Unit (Vitest): `npx vitest run` — `helpers/__tests__/gestures.spec.ts` (synthetic 21-point hands, rotation, facing), `game/__tests__/swarm.spec.ts` (physics invariants: floats, coasts, stops, comet shape, order of engagement, caps…), `game/__tests__/input.spec.ts`, `helpers/__tests__/gestureCode.spec.ts` (the code: order, timing, mistakes, toggling), `helpers/__tests__/avatar.spec.ts` (jitter cut on noisy synthetic hands, lag while following, size constant when the hand scales). (`npm run test:unit` starts watch mode.)
- Arena unit tests: `physics.spec.ts` (resting, stacking, impact speeds, ropes / rods, determinism, destroy), `coupling.spec.ts` (no tunnelling, comet vs crate / boulder / tower / pyramid, spin, props push balls, balloons can be pushed), `distractors.spec.ts`, `arena.spec.ts` (every stage builds / has no overlaps / starts calm / is deterministic; pop, ring, dominoes, combo arithmetic, clear / next / restart, distractors through the real frame loop), `helpers/__tests__/audio.spec.ts` (the ladder, a fake `AudioContext`, mute, rate limit).
- E2E (Playwright, Chromium with a **fake webcam**, `npx playwright install chromium` once): `npx playwright test` with `npm run dev` running. The game is driven through the mouse fallback; ink is measured from the canvas pixels (the floor line is detected as "a row that is mostly ink", so it works at any zoom). `smoke.spec.ts` needs the backend running (it checks the home page reads `/api/app/version` and that no route logs console errors). The gesture code itself can't be driven in e2e (the fake webcam shows no hand) — it is covered by its unit tests.
- Lint / types: `npm run lint`, `npx vue-tsc --build`.

## Feature log
Current state of each feature (not a history — update the bullet when a feature changes).
- **Home** (`/`): logo (`AppLogo.vue`, outline-only, also `public/favicon.svg` as the tab icon and the desktop icons in `../AppIcon/`: one drawing in all places),  title, backend version pill (`GET /api/app/version`), links to How to play, Play, Arena and Camera spike. *Fully wired.*
- **Tutorial** (`/tutorial`): `game/tutorial.ts` (pure: 8 steps, each done by holding its gesture; progress drains when let go; a short settle between steps; skip / restart) fed every frame by `GameView` (`tutorialOn`) with pose, drift, pinch and stop; a guide card (`data-testid` `tutorial-*`) shows the step, camera + mouse instructions, progress bar, then links to the Arena. Nothing saved (it is always available from Home). *Fully wired.*
- **Camera spike** (`/spike`): webcam → hand skeleton + per-hand readout; the debugging tool for tracking and gestures. Logs pose / facing changes to the host console. *Fully wired.*
- **Hand tracking & gestures** (`helpers/`, `composables/`): bundled offline model (GPU, CPU fallback); smoothed signals; poses `open / fist / point / two / pinch`; **facing** (palm vs back of the hand from the knuckle winding + fingertip depth — a back-facing fist = open, flagged separately as `fistBack`); pointing direction; hand speed (drift) and size (distance). Verified on a real webcam in the macOS window.
- **Swarm physics** (`game/swarm.ts`): 60 balls, gravity, drag, bouncing walls / floor, a position correction only against interpenetration; start as a heap in the middle of the floor. All unit-tested.
- **Levitate / drop**: open palm = gravity off (+ kick from the floor); fist = drop.
- **Wave drift**: open hand moving → slow drift of random balls; `reach` (hand size) scales how many and how fast.
- **Move** (point): head-first stream, comet shape, push that grows while held, hand distance sets speed and the top speed cap (only for stream-carried balls).
- **Circle / pinch**: swirl or clump around the centre point (front ball while moving). With `SwarmInput.follow` (avatar mode) the circle's centre is the avatar: a kinematic point with the avatar's smoothed velocity; each ball has its own orbit-spring strength (`followBindSpread`), so a swarm that flies in as a clump shears into a ring around the hand, and the binding is capped (`orbitBindingMax`) so far-away balls aren't slingshotted.
- **Stop** (both hands open): braking drag, lets go of the stream, switches the drift off.
- **Avatar mode** (`/play`): gesture code → hand shown as a tiny, constant-size, heavily smoothed character at its position (one hand); a back-facing fist circles the balls around it, the centre following. Toggle button + `avatar` / code-progress pills; mouse: pointer = avatar, `B` = back-fist. *Fully wired; unit- and e2e-tested with synthetic hands and the mouse. **Not yet tried on a real hand** — the smoothing numbers (`AVATAR`) were tuned on synthetic noise.*
- **Arena** (`/arena`, `game/physics|coupling|distractors|stages|arena|arenaDraw.ts`, `helpers/audio.ts`): five stages of props (crates, dominoes, boulder, wrecking ball, balloons, gongs) and distractors (lantern, fan, whirlpool) that the swarm can hit and that pull on it; goal / score / combo HUD with restart, next (locked until cleared) and a sound toggle; outlined effects (rings, bursts, score text); synthesized sound with a combo ladder. *Fully wired, no stubs. Not yet played with the camera — the gestures reach it through the same `SwarmInput` as `/play`, and the e2e drives it with the mouse fallback; the sound can't be heard in headless tests (a fake `AudioContext` checks the calls).* Nothing is saved between sessions (best scores would need the host's storage: not built).
- **Mouse fallback**: every gesture above can be driven from the mouse and keyboard.
- Not yet verified / not done: Windows (WebView2); a packaged macOS app (needs `NSCameraUsageDescription`); a Release build serving the `.wasm` / `.task` files; on a 1× display the balls are small dots (looks right at 2×).
